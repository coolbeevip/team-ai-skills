# Markdown 文档风格检查规则

本文档用于将《云文档写作样式.docx》的要求转换为 Markdown 风格检查规则，目的是确保上传到飞书文档后仍能稳定映射为对应样式。

## 1. 章节标题规则

### 1.1 层级映射

- 仅允许使用 `#` 到 `####` 四级标题。
- 标题层级必须连续递进，不得从 `#` 直接跳到 `###`，也不得从 `##` 跳到 `####`。

### 1.2 数字编号

- 标题文本中应包含数字编号，以便飞书导入后映射为有序标题。
- 推荐写法：
  - `# 1. 一级标题`
  - `## 1.1 二级标题`
  - `### 1.1.1 三级标题`
  - `#### 1.1.1.1 四级标题`

### 1.3 检查要点

- 检查标题是否与编号一致。
- 检查是否存在跳号、重号、漏号或层级错配。

## 2. 正文与对齐规则

### 2.1 缩进处理

- 列表项下的说明文字、补充段落、子列表，必须使用 4 个空格或 1 个 Tab 缩进。
- 禁止使用全角空格、半角空格手动拼接对齐。

### 2.2 列表嵌套

- 二级列表必须通过缩进表达，不得仅靠连续符号堆叠。
- 列表项的层级关系应清晰可见，避免导入飞书后脱层。

## 3. 代码与变量规则

### 3.1 行内代码

- 行内代码必须使用反引号包裹，例如 `` `code` ``。

### 3.2 独立代码块

- 独立代码块必须使用三个反引号包裹。

### 3.3 列表内代码块

- 如果代码块属于某个列表项，其 ``` 标识符前必须有与父列表项一致的缩进。
- 否则飞书导入后容易把代码块解析为列表外内容。

### 3.4 变量定义

- 变量应写作 ` <*变量名*> ` 这种形式，即尖括号加斜体。
- 检查时重点关注变量是否保持统一，不要与普通文本混淆。

## 4. 高亮块转换规则

- 标准 Markdown 没有原生高亮块语法。
- 建议使用引用块，并在开头标注类型：
  - `> **注意：** 内容`
  - `> **警告：** 内容`
- 如果需要在飞书中转成高亮块，应在检查报告中明确提示。

## 5. 图片与图题注规则

### 5.1 位置

- 图题注必须位于图片语法的下一行。

### 5.2 格式

- 图题注必须加粗，例如 `**图 1. 架构图**`。

### 5.3 检查要点

- 检查图片与题注之间是否存在多余空行。
- 检查题注是否紧跟图片并保持加粗。

## 6. 表格与表题注规则

### 6.1 位置

- 表题注必须位于表格语法的上一行。

### 6.2 格式

- 表题注必须加粗，例如 `**表 1. 字段说明**`。

### 6.3 表头

- Markdown 表格必须包含表头分隔行，例如 `| --- | --- |`。

### 6.4 检查要点

- 检查表格是否缺少表头。
- 检查题注是否与表格贴合，避免导入后断裂。

## 7. 检查反馈建议

- 对不符合规则的行，给出原文、违规规则编号和替换建议。
- 反馈示例：
  - 错误：图片下方题注未加粗。
  - 修改：将 `图 1. 架构图` 改为 `**图 1. 架构图**`。
  - 错误：列表下的代码块未缩进。
  - 修改：在 ``` 前添加 4 个空格，使其隶属于上方列表项。
