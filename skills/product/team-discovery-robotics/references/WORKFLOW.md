# 机器人需求发现与方案工作流

本文件是七个确认阶段的详细执行参考。八步 SOP 与阶段的唯一映射为：阶段一对应步骤 1–3，阶段二对应步骤 4，阶段三对应步骤 5，阶段四和五分别对应步骤 6a、6b，阶段六对应步骤 7，阶段七对应步骤 8。

已有材料能回答的问题先提取事实并标注出处，不机械逐章提问。每个阶段的转换门槛以 `SKILL.md` 的“阶段证据充分性检查”为准。

## 阶段一：场景定义（SOP 步骤 1–3）

目标是把模糊想法转成可计算的需求基线。

1. 引用客户原话重述业务问题，圈出不能直接开发或验收的词，并确认是否存在锁定、优先或候选本体。
2. 确认现行操作、最痛环节、任务频率与峰值、业务基线和最希望改善的指标；缺少数据时标记待调研。
3. 建立 Use Case 清单，用 Who、What、When、Where、Why 定义参与者、对象、触发、环境、业务价值和明确不做。
4. 盘点与任务有关的对象、空间、动态环境、业务系统、合规和安全条件。
5. 用“对象 + 位置 + 状态 + 容差”定义目标状态。
6. 根据 Use Case 建立任务级 Mermaid 状态机骨架和状态转换表，覆盖开始、主要任务、完成、失败、取消和人工介入。
7. 用真实任务故事板逐帧检查信息、动作、空间时间条件和成功证据，再回写状态、Guard、超时、重试、并发和安全监督。

确认产物：Use Case 清单、场景基线、状态机骨架、故事板与发现台账。

## 阶段二：范围冻结（SOP 步骤 4）

目标是冻结 Must/Should/Could/Out，并形成需求和责任基线。

- 从 Use Case、故事板、现行流程、状态机、风险和生命周期活动收集候选需求。
- 记录来源、缺失影响、生命周期阶段和 MVP 状态；没有依据的功能不进入 MVP。
- 区分使命、使能、质量、安全、既有约束、方案决定和 desirement。
- 为关键需求分配 L1/L2/L3，以及硬件、软件、人员、设施和外部系统责任。

确认产物：范围基线、带唯一 ID 的需求清单和责任分配。

## 阶段三：工程指标（SOP 步骤 5）

目标是从场景反推可复核的定量预算。

- 把定位导航、识别、可达性、抓取放置、结果验证、调度、安全和人工接管转成载荷、工作空间、精度、节拍、视场、距离、延迟、可用性、算力、网络与安全等级。
- 对影响选型的指标记录单位、公式或判断模型、输入来源、最低/目标/理想值、设计余量和验证方法。
- 光学、抓取、移动和安全停止分别使用适用模型，不混用经验阈值；经验值记录为待验证假设。

确认产物：硬件能力需求、软件责任需求和工程指标预算。

## 阶段四：系统方案（SOP 步骤 6a）

目标是比较并确定端到端系统与硬件方案。

- 提出至少两个可比较的端到端候选，联网核对当前产品页、数据表、许可和认证。
- 未指定本体时完成本体及配套组件选型；锁定本体时比较增配、环境改造、软件补偿和人工协同路径。
- 给出推荐、备选、淘汰理由、失败模式、降级路径、换型条件、BOM、布置、接口、性能预算和残余缺口。

确认产物：候选比较、推荐系统方案、硬件 BOM、安全与责任边界。

## 阶段五：软件算法（SOP 步骤 6b）

目标是定义与阶段四一致的软件、AI 和算法方案。

- 明确 L1/L2/L3 组件归属、驱动、通信、Skill API、Capability/Motion API、任务编排、业务集成、数据模型和部署拓扑。
- 说明感知、定位建图、导航或操作规划、结果验证、数据与模型闭环和测试责任。
- 需要语音时定义唤醒、ASR、TTS、离线/云端策略和隐私边界；不需要时说明排除理由。
- 只有场景证据要求 VLA 时才进入 VLA 选型，并保留模块化非 VLA 基线。

确认产物：软件架构、AI 感知、导航操作、语音方案和数据闭环。

## 阶段六：MVP 与 PoC（SOP 步骤 7）

目标是收敛最小端到端闭环，并设计验证和实施计划。

- 明确 MVP 内、MVP 外和后续候选，优先选择价值明确、环境稳定、对象有限且容易验收的闭环。
- 为高风险硬件、感知、操作、语音、系统集成和本体适配冲突定义样本、环境、步骤、指标、通过门槛、失败替代方案和责任人。
- 给出现场勘查、采购与样机、基础集成、单能力验证、闭环联调、试点、验收和规模部署的周期区间、依赖与退出标准。
- 每项验收指标包含测试条件、样本量、计算口径和目标阈值。

确认产物：MVP 定义、PoC 合同、实施计划和验收标准。

## 阶段七：方案书汇编（SOP 步骤 8）

目标是形成面向客户和决策者的正式项目方案书。

- 确认 discovery、系统硬件规格和软件规格的范围、需求、型号、版本、指标、接口、责任、商务约定和里程碑一致。
- 关闭关键决策和阻塞后，按 `PROPOSAL-FORMAT.md` 汇编最终价值、方案、边界、配置、实施、验收、商务约定和责任。
- 不把状态机、故事板、范围表、推导过程、候选评分、内部编号或方法论词汇复制进方案书。

确认产物：正式项目方案书终稿。
