# 质量门禁

按本轮请求的格式执行检查，失败只影响依赖该项的交付；不能因为 PNG 未完成而扣住已经可用的 Markdown。检查记录写在交付回复或辅助 `checks.md`，不把制作过程填进阅读正文。

## 事实忠实度

逐一核对标题、中心判断、数字、单位、时间、适用范围、观点归属和来源位置。检查图形编码是否偷偷引入趋势、顺序或因果。计划不写为已实现，相关不写为因果，既有测试改善不写为泛化收益。

双模式从同一底稿检查数值与条件，不能只比较两篇措辞。未解决冲突保留双来源和缺口，暂停相应比较结论。关键风险删掉后若可能改变选择，恢复到结论附近。

## 理解支持度

阅读实际正文，检查重要术语是否能对应具体对象、动作或状态；关键因果是否有解释；案例是否体现必要条件；类比是否被误当作论据。检查读者能否在材料中找到判断依据，而不只是在结尾看到一句总结。

模型审阅能发现潜在问题，不能证明 CEO 或 CTO 已读懂，也不能用同一模型的自问自答冒充独立读者效果。

## 视觉可读性与导出

1. 实际浏览器渲染最终 HTML，至少检查 390 和 430 CSS px 宽度；用户给定目标设备时追加对应宽度。记录实际字体、视口与导出倍率。
2. 检查水平溢出、重叠、文字截断、图片加载、字体缺字、连接方向和图表标签；静态 DOM 尺寸检测不能代替看图。
3. 按手机阅读尺度看 PNG 首、中、尾，并以重叠切片覆盖全文；整图再检查节奏、重复和断裂。缩略图只用于全局检查，不能证明小字可读。
4. Markdown、HTML 和 PNG 中的判断、数字、关键条件、图注与来源一致。HTML 可以不同排版，但不能遗漏正文中的限制。任一内容修改后重新生成并检查图片。
5. 确认文件可打开且 PNG 确为图片；分享需要的文件独立可用。检查没有示例占位、未授权素材、外链字体或泄露内部信息；没有未经用户要求的 CEO/CTO 或“面向管理者”等受众标签。

内容超长时调整叙事或自然分段，不缩小字号。若整图生成失败，报告分段图片替代情况，不宣称整图已验收。

## 环境不足时的降级

| 缺口 | 可交付内容 | 必须说明 |
| --- | --- | --- |
| 没有本地渲染能力 | Markdown、自包含 HTML | PNG 未生成，视觉未验收 |
| 中文字体缺失或有方框字 | 正文、保留字体栈的 HTML 草稿 | 待可用且许可合适的字体重新渲染，现有图不可作为合格成品 |
| 只能打开 HTML，不能导出图片 | Markdown、HTML | 已做哪些浏览器检查，PNG 未生成 |
| PNG 已导出但无法查看 | Markdown、HTML、标为待验收的 PNG | 文件存在不等于视觉通过 |
| 来源缺少关键测试条件 | 保留缺口的忠实版本 | 哪些技术或推广结论尚不能形成 |

不得为补齐格式自动把内部内容发往第三方服务。需要额外工具或披露授权时，具体说明缺口和拟采用方式，不重复索要已给出的授权。

## 真人理解测试

用户要求验证实际阅读效果时，请未参与制作的目标读者复述，并记录真实反馈：CEO 说明核心判断、主要代价和下一步选择；CTO 说明关键机制、适用条件和失败边界。必要时改变一个关键条件，观察能否解释判断变化。

记录受众、材料版本、实际任务和反馈；小样本结果不能外推为普遍效率提升。没有真实作答记录时明确“未做真人理解测试”。
