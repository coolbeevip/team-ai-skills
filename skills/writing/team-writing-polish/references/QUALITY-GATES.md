# 质量门禁

按本轮请求的格式执行检查，失败只影响依赖该项的交付；不能因为 PNG 未完成而扣住已经可用的 Markdown。检查记录写在交付回复或辅助 `checks.md`，不把制作过程填进阅读正文。

## 事实忠实度

逐一核对标题、中心判断、数字、单位、时间、适用范围、观点归属和来源位置。检查图形编码是否偷偷引入趋势、顺序或因果。计划不写为已实现，相关不写为因果，既有测试改善不写为泛化收益。

双模式从同一底稿检查数值与条件，不能只比较两篇措辞。未解决冲突保留双来源和缺口，暂停相应比较结论。关键风险删掉后若可能改变选择，恢复到结论附近。

## 理解支持度

阅读实际正文，检查重要术语是否能对应具体对象、动作或状态；关键因果是否有解释；案例是否体现必要条件；类比是否被误当作论据。检查读者能否在材料中找到判断依据，而不只是在结尾看到一句总结。

模型审阅能发现潜在问题，不能证明 CEO 或 CTO 已读懂，也不能用同一模型的自问自答冒充独立读者效果。

## 杂志编排检查

将美观与技术可读性分开审阅。没有溢出、字号合格和导出成功，并不足以判定杂志品质。

正在选择新风格时，完整制作前检查首屏与全篇骨架预览，并记录具体方向的确认。用户已指定或沿用风格、已有适用确认或明确要求直接完整制作时直接执行，不增加确认。仍待选择时只报告预览完成，不把它当作完整长图。两版需对比主判断、第一焦点和空间分配，不能只比较字数。

- 缩略图中能辨认主标题、主视觉和阅读顺序，重点不被均匀卡片或标签淹没。
- 按手机尺寸阅读时，标题字形有辨识度、断行自然，正文舒适，来源和关键限制仍清楚。
- 看完整长图时，主图、正文、关键句与证据的密度有内容驱动的变化，没有重复模板节奏或无意义长空白。逐块检查：双侧对照是否可比较、步骤是否确有顺序、状态是否区分了条件；换色和角色标签不能算构图变化。
- 对照清单检查原图在分享主线的实际出现位置，不能以 assets 存在或附录保留代替。原图获得足够展示空间，图注紧邻；新增插画与文章主题吻合，不是可互换的通用科技背景。
- 整体字形、颜色、对齐和线条有一致规则；没有靠假刊号、虚构署名或受众标签制造出版感。
- 机制版由主机制图组织解释，观点版由判断组织证据；主线独立可理解，附录未藏起会改变判断的限制。

预览与最终版主线使用相同布局；不能让用户仅凭标题目录确认构图。PNG 的来源说明须可直接阅读，不依赖图片中无法点击的锚点。

发现问题要修改实际版面并重新渲染，不能只给技能添加“更高级”等措辞。记录具体观察与改动；审美自审不能冒充用户认可或真实读者效果。

## 视觉可读性与导出

1. 实际浏览器渲染最终 HTML，至少检查 360、400 和 430 CSS px 宽度；用户给定目标设备时追加对应宽度。记录实际字体家族、可获取的版本、视口与导出倍率；不可获取的字体版本如实注明。
2. 检查水平溢出、重叠、文字截断、图片加载、字体缺字、连接方向和图表标签；静态 DOM 尺寸检测不能代替看图。
3. 按手机阅读尺度看 PNG 首、中、尾，并以重叠切片覆盖全文；整图再检查节奏、重复和断裂。缩略图只用于全局检查，不能证明小字可读，也不能仅凭缩窄的附件预览断言原图模糊。
4. Markdown 与 HTML 对应部分中的判断、数字、关键条件、图注与来源一致；PNG 对应完整主线，附录可只在 HTML 保留并有入口。检查导出区域没有漏掉承重信息。任一内容修改后重新生成并检查受影响图片。
5. 确认文件可打开且 PNG 确为图片；分享需要的文件独立可用。检查没有示例占位、未授权素材、外链字体或泄露内部信息；没有未经用户要求的 CEO/CTO 或“面向管理者”等受众标签。

内容超长时调整叙事或自然分段，不缩小字号。若整图生成失败，报告分段图片替代情况，不宣称整图已验收。

使用固定脚本时，复核 `qa-report.json` 中的内容/文件哈希、实际字体、对比度、视口与分段范围，并在 `qa-report.md` 补充人工观察。未知风格值、低对比度品牌覆盖、来源引用失败或版本不一致均不得静默降级为通过。脚本只覆盖其明确支持的组件，不代表任意 HTML 已通过检查。

## 风格与可访问性

- 五风格对照固定同一受众和内容版本，检查去色后的尺度、构图、图形语言和节奏差异，不能只换色。
- 双模式事实映射一致，各自有不同的阅读任务和骨架；风格不能自动替代受众编辑。
- 预览与最终首屏沿用同一主判断、主图及条件；正文变化后重查，不混用旧图。
- HTML 有语义标题、正常阅读顺序、图片替代文本、可操作来源链接；图表有文字说明。预览选择链接可键盘访问且焦点清楚。
- 自动 DOM 与对比度检查不是读屏实测。未经具体同意，不在真实设备开启读屏、播放声音或改变音频设置；未做真人或设备测试明确记为未验。

## 配图验收

- 对照原文图片清单，确认可用原图优先保留，图注、正文引用及条件仍然对应；被调整或省略的图有具体原因，未以生成图冒充缺失原图。
- 原图移入附录时检查原件和入口可用；证据图未被重新配色或生成式重绘，解释图的线宽、箭头、字体和语义图例一致。
- 每张图能回指正文中的关系、情境或证据；图注区分原始证据、编辑绘图与生成示意，关键条件未被裁掉。
- 数据比例、单位、坐标、箭头方向和并行关系与来源一致；插画没有暗示不存在的产品能力或实际结果。
- 已查看实际生成图片，未用提示词、占位图或未打开的工具返回值代替验收；图中没有多余文字、伪标志或受众标签。
- 素材已在目标项目保存，来源/许可或生成记录可查；Markdown 本地引用、HTML 内嵌和 PNG 中使用相同版本，离线加载无缺图。
- 图片不因固定高度裁切关键信息；手机尺寸下的图中文字、图注与说明可读。明确请求的插画未完成时单独披露，不拿结构图替代并宣称完成。

## 环境不足时的降级

| 缺口 | 可交付内容 | 必须说明 |
| --- | --- | --- |
| 没有本地渲染能力 | Markdown、自包含 HTML | PNG 未生成，视觉未验收 |
| 中文字体缺失或有方框字 | 正文、保留字体栈的 HTML 草稿 | 待可用且许可合适的字体重新渲染，现有图不可作为合格成品 |
| 只能打开 HTML，不能导出图片 | Markdown、HTML | 已做哪些浏览器检查，PNG 未生成 |
| PNG 已导出但无法查看 | Markdown、HTML、标为待验收的 PNG | 文件存在不等于视觉通过 |
| 来源缺少关键测试条件 | 保留缺口的忠实版本 | 哪些技术或推广结论尚不能形成 |

不得为补齐格式自动把内部内容发往第三方服务。需要额外工具或披露授权时，具体说明缺口和拟采用方式，不重复索要已给出的授权。

## 真人理解测试

用户要求验证实际阅读效果时，请未参与制作的目标读者复述，并记录真实反馈：CEO 说明核心判断、主要代价和下一步选择；CTO 说明关键机制、适用条件和失败边界。必要时改变一个关键条件，观察能否解释判断变化。

记录受众、材料版本、实际任务和反馈；小样本结果不能外推为普遍效率提升。没有真实作答记录时明确“未做真人理解测试”。

## 失败案例回归

真实长文曾把全部四张原图移到附录，一版分享图零插图，另一版只留开头流程图；连续正文与来源编号仍通过技术检查。回归应观察：相关原图参与主线，密集原图可局部放大且保留原件；对照、链路、状态有相应结构；预览反映全文；视觉报告写出实际观察。无溢出、三视口通过、文件一致均不能单独证明这些要求已经满足。
