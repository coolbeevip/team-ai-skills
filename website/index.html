Product Order

让技能体系 看起来像 真实可运行的 团队产品

页面的重点不是展示“有很多技能”，而是展示这些技能如何共同形成可信的交付秩序。

01

链式协作

每个技能都读取上游证据，写出下游可以继续使用的产物，形成完整的协作链路。

02

垂直切片

按端到端的垂直切片拆解任务，而不是按层拆分，减少跨任务的隐藏耦合。

03

文件即状态

所有中间产物都是文件，可以版本控制、审查、回溯，状态完全透明。

04

可验证流程

每个步骤都有明确的输入输出和验证标准，确保质量可追溯。

Workflow Lines

先看三条主线 再看具体技能

技能不是平铺的目录，而是围绕团队常见工作组织出来的流水线。

Main line

需求交付链路

把一句需求推进成可评审 PRD、可领取 issue 和可验证实现。

spec review prd issues implement verify PR
Debt line

技术债治理链路

把“系统不稳、维护成本高”转成有证据、有优先级、有验收口径的工程工作。

analyze refine review issues verify
Code line

代码库理解链路

从源码中提取可追溯的系统知识，再转化为开发者和业务都能理解的说明。

onboarding walk brief
Example

一个真实需求 会被加工成什么

可信感来自可检查的中间产物，而不是承诺“AI 会自动完成”。

Input

“导出列表需要支持按状态筛选。”

spec/refine.md

澄清筛选字段、默认值、权限边界和空状态。

spec/reviews.md

识别分页、缓存、权限和导出一致性风险。

prd/prd.md

固化产品规则、验收标准和非目标范围。

issues/001-export-filter.md

拆成可实现、可测试、可验证的工程任务。
