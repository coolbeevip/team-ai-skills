使用场景

主线之外的三条支线

不同团队问题进入不同场景：治理技术债、演进 Agent Harness，或者把 PRD 和设计产物转成适合人类评审的材料。

场景 1

技术债治理

当问题不是新功能，而是系统不稳定、测试不可依赖、维护成本太高时，把技术债变成可评审、可排期、可验收的工程工作。

team-tech-debt-refine → team-tech-debt-review → team-tech-debt-to-issues
场景 2

Agent Harness 演进

当 agent 经常卡在启动、测试、上下文、验证或失败定位上，维护项目级 harness，并用真实开发任务的反馈持续更新 AGENTS.md、CLAUDE.md 和 docs。

team-harness-refine → 真实开发任务试跑 → harness debt
场景 3

人类对齐与文档化

当 AI 产物需要给人评审、给会议讨论、进入正式文档体系时，把机器友好的结构转成更适合人类理解的材料。

team-prd-to-alignment + team-spec-to-functional-design + team-md-style-check
