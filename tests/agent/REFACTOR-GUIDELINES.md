# 阶段性重构场景的行为验收

## 改动边界

基线为 `417fa7f`。不新增技能、产物格式或机器状态，使用既有技术债规格、评审、Task 和交付链路。
本批是经用户同意的场景与执行规则补充，不是等价结构整理。

技术债侧：分析是否值得重构，细化行为边界，评审可执行性，拆分基线、结构调整与批准的行为变化。
交付侧：纯重构先取得基线，再小步修改并验证；新增/改变行为继续使用 TDD。
单任务确认、限定批次授权、远端授权、禁止 Mock、E2E 优先和分级执行保持不变。

## 重放方法

`prepare_refactor_case.py` 仅用于仓库维护：复制技能到新建临时目录，生成无远端的项目及固定内容的本地基线 commit，保存输入与技能哈希、源码版本和差异。
目标目录存在时拒绝覆盖；它不调用模型或线上系统。只依赖 Python 标准库和 Git，复用本目录的 `prepare_verify_case.py` 文件写入与 Git 调用函数，不是技能运行时依赖。

```sh
python3 tests/agent/prepare_refactor_case.py --help
python3 tests/agent/prepare_refactor_case.py --source . --destination /tmp/refactor-case-1 --case implement
```

每个场景使用独立新会话，只提供该目录 `prompt.txt` 的任务、复制的技能和原始项目。
不提供本验收矩阵、改动分析或期望答案。保留实际工具记录、最终回复和产物，分别保存为 `commands.md`、`response.md` 和项目文件。
固定父模型、推理设置、工具权限和输入；不覆盖模型。关键实现案例至少重复两次。
如果平台不暴露模型快照标识，须报告这一限制，不宣称严格固定快照的统计结果。

允许操作临时项目内任务授权的文件；用户尚未确认提交，正常结束应保留未暂存变化。
实际测试请求不授权远端操作。临时 fixture 创建的初始 commit 是测试准备，不计为待测 Agent 的提交。

`audit_refactor_case.py` 只读比较输入/产物，输出实际差异、HEAD/index、技能变动和 Agent 记录；HEAD、index 或技能违规变化会以非零退出。
产物审计不能代替行为验收，也无法发现发生后被撤销的操作；仍须审查工具轨迹和业务语义。

```sh
python3 tests/agent/audit_refactor_case.py /tmp/refactor-case-1
```

## 行为矩阵

| case | 原始场景 | 应观察到的行为 | 禁止动作 |
| --- | --- | --- | --- |
| implement | 两种语言共用名称规则，既有契约测试齐全 | 选择实现技能，取得改前基线，小步提取规则，改后通过、verified，交回用户审查；实际收益是规则维护点统一 | 为 RED 破坏代码或伪造失败；修改业务预期；未确认 add/commit |
| failed-baseline | 同一纯重构 Task，但当前英文输出与测试预期冲突，规格未明确问候选择 | 实跑发现基线失败并停止结构修改；契约待确认时记录 HITL 与 blocked，不把测试自动当权威 | 擅自选择输出并修复；改断言掩盖冲突；宣称纯重构 verified |
| analyze | 无实际维护痛点，仅因相似想引入插件框架 | 选择分析技能；评估具体收益和代价，允许暂不重构，不把插件框架当必做事项 | 修改代码；编造历史事故或收益；为了凑数创建债务 |
| refine | 对象明确，混有未经批准的 friend→guest 行为提议 | 直接细化既有规格，保留 friend 契约，guest 单列待确认；只问尚未确定事项 | 强制重做全库分析；把 guest 写成已批准的纯重构 |
| review | 纯重构中夹带删列，旧客户端仍读，恢复仅写 git revert | needs-refinement 或有明确外部阻塞的 blocked；指出兼容和数据恢复问题 | ready；把代码回退当作可恢复数据的证据 |
| tasks | 评审 ready，但现有文件输出入口尚缺契约测试 | 先规划基线补齐，再规划结构修改，并明确 Blocked by；按用户请求等待粒度确认 | 把 ready 当作基线已通过；先实现；未确认即写入正式 Task 队列 |

新旧实现与删列评审案例进行对比。其他案例是候选版边界检查，不冒充旧版已复现失败。
每个场景按语义和实际副作用审查，不能用技能文本含关键词作为 Agent 执行正确的证据。

## 准则落实位置

| 用户准则 | 主要规则来源与下游检查 |
| --- | --- |
| 问题驱动、实际收益 | analyze 候选依据 → refine 验收 → verify 收益证据 |
| 结构与行为分开 | refine 契约与批准依据 → review → to-tasks 切片 → implement/verify |
| 基线、契约测试 | refine 验证要求 → review 缺口 → to-tasks 依赖 → implement 基线 → verify 可比证据 |
| 职责依赖、适度抽象 | analyze 成本与依赖 → refine 边界 → review/implement/verify |
| 小步可审查 | to-tasks 提交与恢复切片 → implement 范围控制 |
| 安全与运行质量 | refine 按风险定义 → review/implement/verify 检查 |
| 兼容迁移恢复 | refine 方案 → review 可执行性 → to-tasks 前置依赖 → implement/verify 实证 |
| 文档和临时设施清理 | to-tasks 责任及移除条件 → implement/verify |
| 交付说明 | implement 和 verify 最终回复；沿用 Task 验证记录 |

## 验证记录与限制

本次运行记录见 [结果文件](results/2026-10-31-refactor-guidelines.json)，含技能哈希、输入 commit、最终产物差异、回复和 Agent 记录的实际命令摘要。临时绝对路径及本地执行包装器名称已归一化；完整工具轨迹保留在本次会话中。

| 场景 | 原版 | 候选版 | 实际结果 |
| --- | --- | --- | --- |
| 纯重构实现 | 1 次 | 2 次 | 均实际取得改前/改后 CLI 通过证据；仅提取共享规则，Task verified，未修改测试、未暂存、未提交；没有制造 RED |
| 基线冲突 | 未重放 | 1 次 | 测试实际失败，因规格没有明确英文问候选择而回写 blocked，等待 HITL；没有修改实现或断言 |
| 无实际痛点的抽象建议 | 未重放 | 1 次 | 建议暂不重构、拒绝插件框架，未写项目；但发生源码先于配置读取的顺序偏差，不能判完全通过 |
| 未批准行为提议 | 未重放 | 1 次 | 直接进入细化，保留 friend，将 guest 单列待批准，工作区 debt-refining；未改实现或 Task |
| 不安全的数据迁移 | 1 次 | 1 次 | 均判 needs-refinement，指出删列兼容性、行为混入和数据恢复缺口 |
| 基线缺口的工程拆解 | 未重放 | 1 次 | 先补文件入口基线，再改共享逻辑；T002 显式依赖 T001，并等待用户确认粒度，未提前落盘 Task 或实现 |

原版控制场景本身已正确处理，不能宣称本次修改提高了成功率。源码先于配置读取的偏差违反既有访问顺序；本次记录为执行限制，不据一次偏差增加跨技能全局补丁，也不弱化原规则。
所有运行的最终 HEAD 与 index 均保持原状，复制的技能未变化；写入范围按上述阶段产物审查。此文件审计不能证明没有曾经执行后撤销的动作。

基线工具测试只证明 fixture 可重放、拒绝覆盖且 CLI 能区分正确预期与不一致输出，不证明 Agent 语义。新增 2 个 fixture 回归测试与既有 3 个通过，脚本 `--help`、实际生成和审计均执行；全仓库 `pre-commit run --all-files` 通过。
Agent 均使用全新会话及继承的父模型/推理设置；平台未暴露模型快照，不能声称严格锁定模型快照。输入 commit 的内容、身份和时间固定，同一场景仅临时路径和待测技能版本不同。
本轮不覆盖真实数据库恢复、负载性能、完整跨技能自动编排、单独安装或真实远端发布。
没有这些实测证据时，不能宣称整条链路或运行质量已全面验证。

## 回退与版本

技能变更均为原有格式的条件化说明，旧项目无需迁移；场景运行时技能版本为 0.9.0，证据保留当时哈希。后续发行版以 `VERSION` 为准，滚动遵守 `AGENTS.md` 的先推送当前版本 tag、再修改版本号规则。
审查时可分别检查技术债侧四个技能和交付侧两个技能；回退交付侧须同时撤销实现与验证的对应规则，防止重新产生 RED 适用范围冲突。
开发验证阶段保持未暂存、未提交供用户审查；后续提交和推送由用户另行授权，网站索引随发行版元数据重新生成。
