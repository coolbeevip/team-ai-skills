## 保留与改变的行为

- 改变：验证结论明确按既有提交模式交回实现流程，自动批次不追加逐项确认。
- 保留：单任务和逐 Task 模式须用户检查实际差异并确认；未知或变化的批次范围不能继承授权。
- 保留：验证器不提交；失败不得提交；已 committed 复验不得降级；远端操作另需授权。
- 保留：现有测试策略、命名、路径、配置和三类状态合同。未调整团队禁止 Mock 等约定。
- 版本：这是未发布的行为纠错，不是纯结构整理；技能发行版仍为 0.9.0，未改变产物格式或添加格式版本。

## 限制与下一批候选

- Agent 均使用新会话、继承同一父模型及推理配置，无模型覆盖；平台未暴露模型快照标识。
  输入生成器、代码、配置和用户语义相同，但临时路径及初始化 Git SHA 不同。
  这是受控冒烟，不是严格固定快照的统计基准。
- 除自动场景外，原版控制场景未重放；没有真实半年使用会话或旧业务项目样本，未伪造历史失败。
- 未覆盖技能自动选择、完整实现到提交、真实批次恢复及远端副作用；本次文件审计不能证明没有尝试后撤销的操作。
- 单独安装不能判定全面通过：验证技能仍引用相邻实现技能中的测试规则和标准库参考。
  下一批应先确认独立安装合同，再单独处理资源来源、副本同步和缺失资源行为；不能借本次授权修复改变依赖合同。
- 结构压缩、公共规则大规模抽取与历史补丁删除均未实施。应等待对应行为案例与问题证据，避免一次重写全库。
